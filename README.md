# ISKRA — promo site

Nightclub promo site for **iskra.orvadora.com**. React (Vite) front end, Node/Express +
MongoDB back end, with a playable arcade promotion ("Spark Rush") whose leaderboard and
prize codes are enforced server-side.

```
├── client/          React app (Vite)
├── server/          Express API + Mongoose models
└── reference-static-site.html   the original single-file design, kept for reference
```

## Running it

```bash
npm run install:all     # installs client + server deps
npm run seed            # loads events, promo codes and demo leaderboard players
npm run dev             # API on :4310, client on :5173
```

Open http://localhost:5173

> The API runs on **4310**, not 4000 — port 4000 is already used by another project
> on this machine.

## Database

`server/.env` holds `MONGODB_URI`. The cluster is shared with your other projects, so the
URI ends in **`/iskra_promo`** — a dedicated database. Nothing here reads or writes
`applybycazamio`, `noveradatasolutions`, `noveraproperties`, or `test`.

Collections: `events`, `players`, `promocodes`, `subscribers`, `orders`.

`.env` is gitignored. **Rotate the Atlas password** — the current one was shared in plain text.

## Design

One accent (ember `#ff5a1f`), one theme (dark), one corner radius (2px), no eyebrow labels,
no em-dashes. Photography carries the tonal contrast so the UI itself can stay quiet.

### Images need replacing before launch

`client/public/img/*.svg` are **art-directed placeholder plates** (light shafts, haze, grain),
not photographs. Stock services were tried and rejected: a seeded request for a nightclub
crowd returned a field of cows, and the same seed did not return the same image twice.

Drop a real JPEG into `client/public/img/` with the same filename and it inherits the grade
automatically. What to shoot:

| File | Subject | Size |
|---|---|---|
| `hero.svg` | Main floor, wide, crowd lit from behind | 2400x1500 |
| `queue.svg` | The doorway or queue, vertical | 1000x1100 |
| `terrace.svg` | Terrace at dawn, wide | 1800x900 |
| `room-*.svg` | One per space: main hall, basement, terrace, bar, booth, cloakroom | 600x800 |
| `night-1..7.svg` | Seven generic night shots, used per event | 640x400 |

Real photographs want `grayscale(1) contrast(1.25) brightness(.5)` added back in
`.hero-bg img` (see the comment there); the plates ship pre-graded.

### Other things to fill in

- `client/src/site.js` holds the address and social URLs. Empty socials are not rendered,
  so the footer never ships a dead link. Add the real URLs to turn them on.
- Event times are the venue's wall clock, stored as UTC and formatted as UTC, so a visitor
  abroad sees the real door time rather than one shifted into their timezone.

## The game promotion

60-second reflex game. Orange sparks score, gold embers pay 3×, dark sparks penalise,
and consecutive hits build a multiplier up to 5×.

| Rank at season close | Prize | Code issued |
|---|---|---|
| 1 | $10 flat ticket | `ISKRA10-XXXX` |
| 2–5 | 50% off (max 2 tickets) | `ISKRA50-XXXX` |
| everyone else | 10% off | `PLAYED10-XXXX` |

Codes are unique per player, generated by the server, and validated against the database at
checkout. A player's earned tier is never downgraded if others overtake them.

**Enforced server-side** (not in the browser, so it can't be edited around):
- 3 attempts per player per day
- a session token issued at signup is required to submit a score
- scores above 150,000 and round lengths outside 50–75s are rejected
- rate limiting: 120 req/min per IP, 20/min on writes

## API

|---|---|---|
| GET  | `/api/events` | Lineup |
| POST | `/api/players` | Sign up / sign back in by email |
| GET  | `/api/players/:id` | Attempts left, best score, prize code |
| POST | `/api/scores` | Submit a round, returns rank + prize |
| GET  | `/api/leaderboard` | Top 10 (+ the caller's own row) |
| POST | `/api/promo/validate` | Validates campaign and prize codes |
| POST | `/api/subscribe` | Newsletter |
| POST | `/api/orders` | Demo checkout — records intent, takes no payment |

## Deploying to iskra.orvadora.com

**Live at https://iskra.orvadora.com** (Let's Encrypt cert, valid to 18 Nov 2026).

```bash
./deploy.sh          # upload, build, restart
./deploy.sh --seed   # same, then reload events/promo codes/demo players
./deploy.sh --logs   # tail the app container
```

### How it fits on the VPS

That box (`srv1914118`, Ubuntu 24.04) already runs **orvadora.com** — its own compose stack
with `web`, `api` and a Caddy that owns ports 80/443. ISKRA does **not** bring a second
proxy; it runs one container that joins the existing `orvadora_app` network, and the
orvadora Caddy publishes it:

```
/root/home/orvadora    web + api + caddy   (ports 80/443)   ← existing, untouched
/root/home/iskra       iskra-app :4310     (internal only)  ← this project
```

The site block appended to `/root/home/orvadora/Caddyfile`:

```
iskra.orvadora.com {
    encode zstd gzip
    reverse_proxy iskra-app:4310
}
```

Timestamped backups of that file are kept next to it (`Caddyfile.bak.*`).

### Two traps this deploy hit — worth knowing before editing that Caddyfile

1. **`caddy reload` silently does nothing.** The Caddyfile is bind-mounted as a *single
   file*, so the container is pinned to the inode that existed when it started. Edits on
   the host are invisible to it and reload reports `config is unchanged`. The container has
   to be recreated: `docker compose up -d --force-recreate caddy`.
2. **`caddy validate` inside the running container validates the stale file**, so it always
   passes. Validate the host file in a throwaway container instead, and pass
   `ACME_EMAIL` — the config references `{$ACME_EMAIL}` and fails to parse without it.

`deploy.sh` does both correctly. It only recreates `caddy`; `web` and `api` keep running,
so orvadora.com drops for roughly a second during a deploy.

### SSH

A dedicated key was generated at `~/.ssh/iskra_deploy` and added to the server's
`authorized_keys`, so deploys need no password. The root password still works.

### Secrets

`server/.env` is gitignored but **is** uploaded by rsync — that is how `MONGODB_URI` reaches
the server. It is never baked into the image (`.dockerignore` excludes all `.env` files);
compose injects it at runtime.

That file also holds `SSHline` and `Access_toVPS`. The app never reads them. A VPS root
password in an application env file will eventually leak — move it to a password manager
and consider disabling password SSH now that key auth works.

### The image

Multi-stage: node:22-alpine builds the client, the runtime stage carries production server
deps plus `client/dist` only. 276 MB, runs as the unprivileged `node` user, with a
healthcheck on `/api/health`.
